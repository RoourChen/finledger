# 业务规则（rules）

> 实现见 `../rules.py`（纯函数）与 `../writeoff.py`（依赖数据库的核销校验）。

## 1. 金额勾稽

- 含税 = 不含税 + 税额
- 税额 ≈ 不含税 × 税率
- 缺项自动补算：已知「不含税 + 税率」→ 算税额与含税；已知「含税 + 税率」→ 算不含税与税额。
- 校验偏差超阈值 → 阻止入库，提示人工核对。

## 2. 回款状态自动推导（不手填）

| 已核销金额 | 状态 |
|---|---|
| = 0 | 待核销 |
| 0 < x < 回款金额 | 部分核销 |
| = 回款金额 | 已核销 |

## 3. 方向校验

- 销项发票只挂客户；进项发票只挂供应商（「两者」单位都可）。
- 收款核销销项发票；付款核销进项发票。

## 4. 核销约束

- 核销按含税金额。
- 作废 / 红冲发票不参与核销（红字发票无收款义务）。
- 核销金额不能超过回款剩余可核销金额，也不能超过发票可核销金额。
- 同一回款对同一发票只能有一条核销（表级 UNIQUE 兜底）。

## 4.1 发票可核销金额（红冲 / 作废联动）

> 口径（含税，与核销一致）：
> **蓝字发票可核销金额 = 含税金额 − 已核销金额 − 已红冲金额，不得为负**

- 蓝字发票被部分/全部红冲后，可核销金额自动减少对应红冲金额。
- 红字发票本身不允许再被核销。
- 作废发票金额全部不可核销，且不参与后续任何统计（报表口径已排除）。
- 红字发票金额以正数登记（表示红冲金额量），关联字段 `related_invoice_code` 存原蓝字发票的内部编号。
- 强校验：
  - 新增/修改红字发票时，红冲金额不得超过原蓝字发票的可核销金额。
  - 修改发票含税金额时，含税金额不得小于「已核销 + 已红冲」。
  - 作废前：若发票已有核销或红冲记录，先撤销/处理再作废。
  - 修改回款金额时，金额不得小于已核销金额（先撤销核销再改）。

## 5. 唯一性

- 客户/供应商编号、税号、合同编号、回款单号、发票编号唯一。
- 发票「代码+号码」唯一（防重复录入）。

## 6. 异常交人工

金额对不上、重复录入、方向不符、关联单位不一致 → 明确提示，不硬猜。
